# 補貨檢查

> 這是**挖空模板**。標 ★ 的地方要你自己填。
> 重點是「數字一定要從盤點資料抄，不能自己編」，而且每個數字都要能驗算。

## 什麼時候用

- 跑完 `npm run simulate`，要決定下一版策略每樣菜備幾份時
- 在瀏覽器玩完一天，想看「倉庫盤點」頁的結果該怎麼調整時

## 資料從哪裡來

在 `web-lab` 資料夾執行：

```text
npm run simulate -- plans/策略檔.json --json
```

每一天的 `inventory` 欄位，是那天每樣上架的菜的盤點：

| 欄位 | 意思 | 怎麼驗算 |
|---|---|---|
| `name` | 菜名 | — |
| `stocked` | 早上備了幾份 | 策略檔裡的 `qty` |
| `sold` | 賣出幾份 | 打烊報表 |
| `waste` | 報廢幾份 | 備貨 − 賣出 |
| `missed` | 賣完之後，還有幾位客人想買卻沒買到 | 客人卡片上「賣完了」的數量 |
| `status` | `ok` 正常、`out` 缺貨、`over` 報廢過多 | 規則書「倉庫盤點」 |
| `suggest` | 明天建議備幾份 | 賣出 ＋ 沒買到 |

## 步驟

1. 執行上面的指令，讀每一天的 `inventory`
2. 先驗算：`waste` 有沒有等於 `stocked − sold`？對不上就停下來回報，**不要用錯的資料做建議**
3. 挑出 `status` 不是 `ok` 的菜
4. 建議備貨量要不要再調整：
   - **資料驗證（每一筆都要先過，沒過就不提建議）**：
     - 備貨、賣出、報廢、沒買到都必須是非負整數，且賣出不能大於備貨
     - 報廢必須等於 備貨 − 賣出
     - `status` 要符合規則書：賣完後有人沒買到 ＝ `out`；報廢 5 份以上 ＝ `over`；其他 ＝ `ok`
     - `suggest` 要等於 賣出 ＋ 沒買到
     - 資料缺漏或互相矛盾時，指出是**哪一天、哪樣菜、哪個欄位**有問題，並**停止提出該筆資料的備貨建議**
   - **只針對缺貨（`out`）或報廢過多（`over`）的菜提出調整建議**；`ok` 的菜不調整
   - **基礎建議量 ＝ 賣出 ＋ 賣完後沒買到**，要寫出算式（例：10 ＋ 12 ＝ 22）
   - **把「依今天資料算出的基礎建議」和「考慮隔日條件後的調整」分開寫**：
     - 沒有隔日需求的證據（預告、天氣、事件、宣傳費、星等）時，**只給基礎建議，不自行加固定百分比**
     - 有證據時，寫出證據是什麼、為什麼調、調多少，並列出算式
   - **建議備貨成本**：依規則書的單份成本計算並列出算式（例：招牌鍋貼 22 份 × 35 元 ＝ 770 元）
   - **判斷下一版「完整備貨」可不可行**，要檢查所有餐點的：總份數 ≤ 80、上架 ≤ 4 樣、總備貨成本 ＋ 宣傳費 ≤ 可用資金。缺少任何一項必要資料（其他菜的備貨量、宣傳費、現金）時，明確寫「**尚無法確認可執行性**」，不要把單一道菜的建議當成已驗證的完整策略
5. 同一樣菜連續幾天都缺貨或報廢過多，要怎麼提醒：
   - 同一道菜在**相鄰兩天**都是缺貨，或都是報廢過多：提醒「這是持續現象」，列出各天的數字（缺貨寫備、賣、沒買到；報廢寫備、賣、報廢）
   - 只有一天資料時，**不推測多天趨勢**，只說「資料只有一天，無法判斷是否持續」
   - 中間隔一天不算連續；一天缺貨、一天報廢也不算同一種持續現象，分開列出
   - 只講事實與天數，不判斷原因，原因交給 result-review
6. 用下面的回報格式回報

## 回報格式

```text
策略檔：
驗算結果：通過 / 第 N 天的 ○○ 對不上（寫出哪個欄位、哪個數字）
第 N 天：
  缺貨：菜名 備 … 賣 … 沒買到 … → 建議 …
  報廢過多：菜名 備 … 賣 … 報廢 … → 建議 …
補充欄位（每道缺貨或報廢過多的菜都要寫）：
  基礎建議：賣出 … ＋ 沒買到 … ＝ …
  隔日調整：（沒有證據就寫「無」；有就寫證據與算式）
  建議備貨成本：… 份 × … 元 ＝ …
持續現象：菜名 連續 N 天 缺貨／報廢過多（列出各天數字）；資料只有一天就寫「無法判斷」
可執行性：總份數 … ／ 80、上架 … ／ 4、總成本 ＋ 宣傳費 ＝ … ／ 可用資金 …；缺資料就寫「尚無法確認可執行性」
下一版每天建議的備貨量：
```

## 寫完檢查

- [ ] 每一個數字都能在盤點資料裡找到
- [ ] 我再加的檢查：
  - [ ] 所有原始數字都來自使用者提供的盤點資料，或上面「資料從哪裡來」列出的來源；算出來的數字都有列算式
  - [ ] 每樣菜都驗過：非負整數、賣出 ≤ 備貨、報廢 ＝ 備貨 − 賣出、狀態、`suggest ＝ 賣出 ＋ 沒買到`
  - [ ] 有問題的資料都指出了哪一天、哪樣菜、哪個欄位，而且沒有對它提出建議
  - [ ] 只對缺貨或報廢過多的菜提出建議；「基礎建議」與「隔日調整」分開寫
  - [ ] 「持續現象」只用相鄰兩天，且有列出各天數字
  - [ ] 沒有確認完整備貨的總份數、總成本、宣傳費、可用資金時，寫的是「尚無法確認可執行性」
